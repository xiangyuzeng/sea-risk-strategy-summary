| 阶段 | 作用 |
|---|---|
| 一、配置前评估表 | 判断策略是否可以进入配置阶段，重点防止**规则本身设计错误、对象理解错误、误伤风险未识别** |

## 三、命中样本的证据分层

这是本文档里最值得参考的部分 —— 对命中样本没有笼统地下结论，而是**逐段说明每一部分是被什么证据认定为黑产的**。

命中样本共 **200 PV / 91 UV**，风险样本量 0，暂无法判断样本量 0，准确率 100%，误伤比例 0。
200 个 PV 被拆成三组分别举证：

| 组 | PV | 认定依据（已去除具体信号名与厂商名） |
|---|---|---|
| 第一组 | 48 | 由**第三方风控引擎独立判定**为黑产：同设备、同 IP 批量操作多个账号，反复使用新人优惠以同一低价金额下单 |
| 第二组 | 9 | 因**号码与设备维度的聚合异常**叠加客户端属性异常而被拦截 |
| 第三组 | 143 | 由**号码属性与客户端属性异常**认定：绝大多数为高风险号码来源，且存在一个设备短期内对应多个手机号；下单金额一致 |

**为什么这个分层有价值**：结论不是靠单一特征下的，而是按「这部分样本是被什么认定的」逐段举证 ——
其中一组由第三方引擎独立判定，另两组由号码、设备与客户端维度的异常认定。
这种分层举证正是「不得单一特征定性」所要求的论证方式。

## 五、流程层面的观察

以下均为本条记录自身可见的问题：

1. **必填字段仍有空白。** 「是否达到命中样本参考门槛」「发布前评估结论」「leader 审批结论」
   「上线后监控责任人」均为必填但未填写，而「当前状态」已标记为确认 —— 审批链路留痕不完整。

2. **风险画像六项全部空白。** 代下行为是否明显、IP / 设备是否聚集、手机号是否命中猫池或高风险标签、
   API 链路是否异常、设备指纹是否高风险、礼品卡转赠是否异常 —— 六项均未填写。
   本例中黑产判定的质量是由「黑产评估依据说明」这段自由文本撑起来的，而不是由这六个结构化字段。
   **结构化字段空着、自由文本写得好**，说明判定质量依赖填写人的自觉，而非流程约束。

3. **近 7 日同期基线未填。** 「近 7 日同期平均调用量 / 用户量」两项留空，
   因而无法判断本次观察窗的量级相对历史是否正常。

4. **硬特征规则的固有脆弱性。** 两条规则都以具体字段取值的等值判断为主（其中一条还含一个二选一的子条件）。
   这类规则的命中条件高度具体，对抗方只要调整所依赖的特征即可使其失效 ——
   适合在应急期快速止血，不适合作为长期主力。文档本身没有记录这一权衡，
   也没有为该规则设定有效期或复评时间点。

**据此可提的改进项**：命中样本参考门槛应设为硬性卡点；风险画像六项在判定黑产时应强制填写，
与自由文本互为印证；近 7 日基线应自动带出而非人工填写；
硬特征类规则应附带有效期或复评时间点，避免长期挂在线上而无人复核。
